## What's new in 1.1.2

Scout 1.1.2 is a maintenance release with dependency fixes and expanded
compatibility coverage. It includes the changes merged since v1.1.1.

### Dialog and rendering compatibility

- Update Terminal.Gui from `2.5.1-develop.171` to `2.5.1-develop.183`.
  Clearing or shortening a dialog list keeps selection and scroll state valid;
  Begin-only UI sessions preserve the caller's synchronization context.
- Add eight regression cases covering cleared/shortened lists, resized plan
  and result summaries, nested sessions, and hidden approval hotkeys. Scrolled
  summary dialogs keep the selected package visible after resizing, and a
  hidden local Install button cannot approve a plan through its hotkey.
- Update Markdig to `1.5.1` for whitespace, escaping, indentation, and autolink
  parsing fixes. Existing compact Details links and their complete destinations
  retain rendered compatibility coverage.

### Updated runtime and development dependencies

- Update the file-system abstractions to `22.3.0` and Microsoft.Extensions
  libraries to `10.0.14`, with all portable, Identity, and test locks aligned.
- Use .NET SDK `10.0.403` and Microsoft.Testing.Platform `2.5.2`. Keep test
  telemetry on compatible Application Insights 2.x: 3.x removes an API the
  current test-platform extension still uses.
- Refresh CI, artifact-transfer, Pages, and CodeQL actions. Group related
  dependency updates to keep CodeQL modules, test-platform components,
  configuration libraries, and file-system wrappers compatible.

### Downloads and validation

The portable ZIP remains the complete COM-capable download for Windows x64
and ARM64. Keep its companion DLLs beside `wingetscout.exe`. The standalone
EXE uses the WinGet CLI backend. The interface and shortcuts are unchanged;
the existing 1.1.1 screenshots and mock demonstrations still illustrate them.

Validation includes 757 automated tests, Windows x64/ARM64 portable and Identity
Native AOT publishes, companion-file checks, graceful mock startup, and CodeQL.
Native Windows Terminal input/mouse/font behavior, live COM activation, and
installed MSIX operation are not established by those checks. Native ARM64 COM
installs remain a [known limitation](https://github.com/harder/wingetscout/blob/main/docs/architecture.md#known-com-limitations);
use the CLI backend for affected operations.

See the [Terminal.Gui review](https://github.com/harder/wingetscout/blob/main/docs/terminal-gui-update-review.md)
and [transitive dependency review](https://github.com/harder/wingetscout/blob/main/docs/transitive-dependency-review.md)
for source comparisons, adoption decisions, and validation limits. Updates
